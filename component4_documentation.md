## 1. Project Overview

### What Does It Do?

Component 4 is an **AI-powered skill gap analysis system** that helps recruiters and candidates understand how well a candidate matches a specific job role. It:

1. Takes a candidate's skills, experience, education, and scores as input
2. Compares them against the requirements for their target job role
3. Uses a trained Machine Learning model to **predict hire probability**
4. Shows exactly **which skills are missing** (required vs optional)
5. Generates a **personalised monthly learning plan** with real course links
6. Draws a **career progression path** (Junior → Mid → Senior → Lead → Principal)
7. Tracks the candidate's **learning progress** skill by skill

### Who Uses It?

| User | Purpose |
|------|---------|
| **Recruiter** | View candidate skill gaps, hire predictions, and analytics dashboard |
| **Candidate** | Understand what to learn and track progress toward career goals |
| **HR Manager** | View aggregate analytics across all roles and candidates |

### Step 2 — ML Inference Engine (`backend/services/ml_engine.py`)

This is the **brain** of the system. It loads all artifacts at startup and runs analysis on demand.

#### Key Functions:

**`compute_gap(skills, job_role, experience_years)`**
- Compares the candidate's skills against the job's required/optional list
- Uses **fuzzy matching** (substring check) so "AWS/Azure/GCP" matches "AWS"
- Returns: `gap_score` (0–1), `missing_required`, `missing_optional`, `skill_match_pct`
- Formula: `gap_score = 0.70 × req_score + 0.30 × opt_score` then blended with experience

**`gap_severity(score)`**
- Converts the gap score into a label:
  - `≥ 0.80` → **Low** (candidate is a strong match)
  - `≥ 0.55` → **Medium** (some gaps but manageable)
  - `< 0.55` → **High** (significant skill gaps)

**`build_feature_vector(skills, job_role, experience_years, ...)`**
- Converts human-readable inputs into a numeric DataFrame row
- Exactly matches the feature columns used during training
- If an unknown value is passed (e.g. unrecognised education), it uses a safe default

**`run_skill_gap_analysis(...)`**
- The main function — orchestrates all 9 steps:

```
1. compute_gap()             → gap_score, missing skills, match %
2. build_feature_vector()    → numeric ML input row
3. _clf.predict_proba()      → ML hire probability (0.0–1.0)
4. Blend with CV/Interview   → hire_prob = 0.60×ML + 0.40×scores
5. Categorise missing skills → Technical / ML-AI / Cloud-DevOps / Security / Data-DB
6. Derive interview gaps     → if interview_score < 60 → knowledge gaps
7. Build resource recommendations → course links per missing skill
8. Build monthly learning plan    → 2 skills per month with courses
9. Build career suggestions       → role path + lateral moves
```

Returns a single large dictionary with everything the frontend needs.

## 5. Key Features Explained

### Feature 1 — Skill Gap Analysis

The system compares a candidate's skills against what the job requires using **fuzzy matching** (so "AWS/Azure/GCP" correctly matches "AWS"). It calculates:

- **Skill Match %** = (required skills present / total required) × 100
- **Gap Score** = weighted formula combining required skills, optional skills, and experience
- **Gap Severity** = Low / Medium / High label from the gap score

### Feature 2 — ML Hire Probability Prediction

The trained Logistic Regression model takes 60+ features (skills, education, level, experience, certifications, projects) and predicts the probability of hire. This is then blended with CV and interview scores if available:

```
Final Hire Prob = 60% × ML prediction + 40% × avg(CV score, Interview score)
```

### Feature 3 — Personalised Learning Plan

For every missing required skill, the system finds a real online course (Coursera, Udemy, fast.ai, Kaggle). Missing skills are grouped into monthly chunks of 2:

```
Month 1: SIEM Fundamentals (4 weeks · Beginner) + Penetration Testing (4 weeks · Beginner)
Month 2: Python for Everybody (3 months · Beginner)
...
```

### Feature 4 — Career Path Visualisation

Shows the candidate's position on the career ladder for their role. For example, a Data Scientist with 3 years experience is at:

```
Junior DS → [Data Scientist] → Senior DS → Lead DS → Principal DS → Chief Data Officer
               (current)
```

Also shows **lateral moves** (e.g., a Data Scientist can move to ML Engineer or Database Administrator).

### Feature 5 — Skill Progress Tracking

Candidates (or HR) can mark individual skills as:
- **Not Started** (grey dot)
- **In Progress** (amber dot)
- **Completed** (green dot)

The overall completion percentage updates in real time.

### Feature 6 — Analytics Dashboard

Provides organisation-wide insight:
- Which roles have the most candidates
- Distribution of gap severities (High/Medium/Low)
- Top skills that are most commonly missing across all candidates
- Leaderboard of best-fit candidates by hire probability

## 6. ML Algorithms Explained

### Training Data

- **Source:** `job_dataset_real_titles_10000.csv` (10,000 records, 22 columns)
- **Columns used:** Job Role, Required Skills, Skills, Experience (Years), Education, Job Level, Work Mode, Certifications Count, Projects Count, Salary (USD/Year)
- **Target Variable:** `1` if salary is in the top 25% (hire-worthy), `0` otherwise

### Feature Engineering

| Raw Column | Transformed To |
|-----------|---------------|
| Education | Ordinal integer (1=Bootcamp, 6=PhD) |
| Job Level | Ordinal integer (1=Junior, 5=Principal) |
| Work Mode | Ordinal integer (1=On-Site, 3=Remote) |
| Job Role | One-hot encoded columns (1 column per role) |
| Required Skills | Binary flags (1=skill present, 0=absent) for 40 skills |
| Certifications Count | Numeric + binary Has_Cert flag |
| Projects Count | Numeric |
| Experience (Years) | Numeric |

**Total Features: ~60 columns**

### Models Compared

| Model | Accuracy | F1 Score | AUC |
|-------|----------|----------|-----|
| Random Forest | ~95% | ~91% | ~99% |
| Gradient Boosting | ~95% | ~91% | ~99% |
| **Logistic Regression** | **95.75%** | **98.25%** | **99.36%** ✅ |

The **Logistic Regression** model was selected as it achieved the highest AUC score. AUC (Area Under the ROC Curve) close to 1.0 means the model correctly ranks "hire-worthy" candidates above others almost perfectly.

### Inference (Prediction Flow)

```
New candidate data
        ↓
build_feature_vector()   → 60-column DataFrame (same format as training)
        ↓
_clf.predict_proba()     → [probability of reject, probability of hire]
        ↓
Take index [1]           → raw hire probability (e.g. 0.72)
        ↓
Blend with CV/interview  → 0.60 × 0.72 + 0.40 × (avg scores/100)
        ↓
Clamp to [0.0, 1.0]      → multiply by 100 → final hire probability %
```
